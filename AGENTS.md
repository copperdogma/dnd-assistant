# Project instructions

This is Cam's Markdown umbrella for RPG enhancement tools and the optional long-term virtual DM vision. It owns synthesis, pointers, decisions, and cross-component questions. It does not own the implementations in sibling projects.

## Resume

1. Read README, docs/scope.md, and docs/constraints-and-next-steps.md.
2. Use docs/components.md to find owners and docs/sources.md to establish provenance and freshness.
3. Inspect current Git status and relevant source files before updating status claims. The initial Echo Forge and projector checkouts were dirty and behind their cached origin/main refs; do not reset, stash, merge, or overwrite them for umbrella maintenance.

## Maintain

- Keep the structure compact. Add useful content to existing docs before creating templates, story systems, methodology graphs, or app scaffolds.
- Keep docs/ideal.md short and outcome-only. Put mechanisms in ideas/integrations and constraints in the constraints document.
- Distinguish **Cam's decisions**, **historical vision**, **implemented evidence**, **assistant proposals**, and **unknowns**. Suggestions do not become decisions without Cam choosing them.
- Date material status changes, identify sources and evidence limits, and cross-link rather than copying entire source documents. Reconcile old inbox claims against stories, code, and newer decisions.
- A local modification, a story marked Done, a passing simulation, and physical table acceptance are different evidence. Do not turn one into another.
- Preserve human GM control and fast correction. Projection must remain optional. Any projection rig must sit on a tripod beside the table; ceiling mounting is unacceptable.
- Initiative/player/miniature tracking belongs to a separate component or explicit integration proposal. Do not silently expand Echo Forge or RPG Map Projector's MVP.
- Do not treat Echo Forge's internal headless session as a published library or remote-control service. Do not treat future NPC/image/lore namespaces as shipped extractors.
- Component repositories, private notes, and local Codex memories are read-only sources unless separately authorized. Follow a component's own instructions when work there is explicitly requested.
- Cam authorized creation and publication of the public `copperdogma/dnd-assistant` GitHub repository on 2026-10-24. This authorization covers checking in and publishing the umbrella documentation; dependency installs, feature implementation and component edits still require separate authorization. Keep private module text, credentials, and personal contact details out of this umbrella.

## Check documentation changes

Reread changed documents for conflicting status claims. Verify Markdown relative paths and anchors, confirm local pointers exist, and check new repository links against accessible source files. Record unavailable sources honestly. No application build or dependency installation is needed for this project.
